The hard gate: ground before asking

  1. Read docs/system/README.md and its topic map.
  2. Read the target and complementary feature-docs.
  3. Read relevant vocabulary, ADRs, learnings, specs/tickets and GitHub issues labelled pending.
  4. State facts, existing seams and genuine unknowns.
  5. Ask the human only for decisions the repository cannot answer.
This happens before the first grilling or Wayfinder question, before Wayfinder mutates the tracker, and before implementation starts.

Direct routes

Simple decided work stays in the current chat. A complete brief can feed to-spec directly when the user requests an AFK contract.

Standalone grill

Only after proving that a genuine decision remains, creates a grill:session issue. Zero open decisions means zero grill.

Wayfinder

For work that is both multisession and still foggy, uses a tracker map, decision tickets and resolution comments as the trail.

Feature memory

Lives in docs/system/, CONTEXT.md and ADRs — never in the raw session transcript.

Tracker protocol

The setup verifies and creates only missing labels. Standalone grills use grill:session + ready-for-human. Wayfinder needs wayfinder:map, wayfinder:research, wayfinder:prototype, wayfinder:grilling and wayfinder:task. The implementation queue also uses spec, ready-for-agent, needs-info, needs-triage and wontfix.

Labels are operational state. The detailed decisions and current technical truth remain in repository docs.
